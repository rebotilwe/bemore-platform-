Requirement 3

Mentee Meter (Live Interaction Layer)

Chairman's Requirement

Implement a live question interface that aligns with the summit programme, allows real-time responses, displays aggregated results, and feeds into our database.

Delivered — Custom Built, Fully Owned

Rather than embedding a third-party tool, we built a complete live polling system directly into the BeMore platform. All data feeds into our MongoDB database — no external dependencies.

4 question types: Multiple Choice, Word Cloud, Rating Scale, and Open Text.

Real-time results: Uses Server-Sent Events (SSE) — when someone votes, all connected viewers see results update instantly (under 100ms).

Anonymous voting: No login required. Session-based deduplication prevents double-voting per question at the database level.

Mobile-first: All vote buttons meet 48px minimum touch targets. Font sizes prevent iOS auto-zoom. Works on any phone via QR code scan.

How It Works at the Summit

Admin Flow (Control Panel)

Step 1: Admin goes to Dashboard → Mentee Meter → selects a poll → clicks "Activate".

Step 2: Admin clicks "Start First Question" in the Control Panel.

Step 3: All attendees on /#/mentee-meter instantly see the question appear on their phones.

Step 4: Admin watches live results update in real-time on the Control Panel.

Step 5: Admin clicks "Next Question →" to advance. All phones update simultaneously.

Step 6: Admin clicks "Close Poll" when the session ends.

Attendee Flow (Phone)

Step 1: Scan QR code → land on BeMore → tap "Live Poll" in the navigation.

Step 2: See the current question. Tap an option to vote (Multiple Choice), type a response (Word Cloud / Open Text), or select a number (Rating).

Step 3: After voting, see the live results chart updating as other attendees vote.

Step 4: When admin advances, the next question appears automatically — no page refresh needed.

Technical Note

The Mentee Meter uses Server-Sent Events (SSE) for real-time updates — zero external dependencies. The backend holds connections in memory and broadcasts vote results to all connected clients instantly. This architecture handles 500+ concurrent voters on a single Railway container. All poll responses are stored in MongoDB alongside application data for unified analytics. An in-memory cache layer with debounced broadcasting ensures fast response times even under heavy voting load.
